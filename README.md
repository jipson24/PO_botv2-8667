# Pocket Signal Bot

Сканер валютных пар Pocket Option со стратегией Smart Money и рассылкой сигналов в Telegram.
Дашборд на порту из `__ports.cjs` показывает сигналы, watchlist и состояние движка.

## Что делает

- Тянет свечи с родного WS-фида Pocket Option (`api-eu.po.market`) по cookie-сессии — только так доступны OTC-пары.
- Фильтрует пары по payout 82–92% и берёт лишь валютные пары.
- Считает мультитаймфрейм: 30m задаёт bias (структура, BOS/CHoCH, order block, FVG, premium/discount), 15m подтверждает, 5m даёт триггер (свечной паттерн, MACD, RSI, уровни).
- Публикует сигнал только на закрытии 5m свечи и только если уверенность ≥ порога (по умолчанию 80%).
- Рассылает сигнал подписчикам Telegram и пишет в базу. Автотрейдинга нет — только сигналы.
- Всё время в сообщениях и на дашборде — киевское (`Europe/Kyiv`).

## Команды бота

`/start` подписка · `/signals` последние сигналы · `/pairs` watchlist · `/status` состояние движка и фида · `/threshold 80` порог уверенности · `/stop` отписка.

## Переменные окружения

Все живут в корневом `.env` (см. `.env.template`). Обязательные для работы движка:

| Переменная | Зачем |
|---|---|
| `POCKET_OPTION_SSID` | Сессия PO целиком, вместе с `42["auth",{...}]`. Источник свечей. |
| `POCKET_OPTION_DEMO` | `0` — реальный счёт, `1` — демо. Должно совпадать с `isDemo` в сессии. |
| `POCKET_OPTION_UID` | UID из той же сессии. |
| `POCKET_OPTION_UA` | User-Agent браузера, в котором выписана сессия — PO сверяет его. |
| `TELEGRAM_BOT_TOKEN` | Токен от @BotFather. Без него рассылка выключена, сигналы идут только в базу. |
| `DATABASE_URL` / `DATABASE_AUTH_TOKEN` | Turso. База удалённая, поэтому подписчики, настройки и история сигналов переживают redeploy. |

## Эксплуатация

- **Сессия PO — расходник.** PO привязывает её к браузеру и UA и со временем инвалидирует. Когда фид отвалился, `/status` и карточка на вкладке «Настройки» покажут состояние `нет доступа`: нужно зайти в PO в браузере, забрать свежий кадр `42["auth",...]` и обновить `POCKET_OPTION_SSID`. Пары в диапазоне 82–92% — это OTC, без живой сессии они не сканируются.
- **Один экземпляр бота.** Telegram отдаёт long-polling только одной копии. Если параллельно крутится dev-сервер в песочнице и продакшен, они будут отбирать друг у друга обновления — в логах появится «тот же токен опрашивает другая копия бота». Держи запущенным что-то одно.
- **Часы брокера.** PO отдаёт метки свечей в своём серверном времени (замерено +2 ч к UTC). Сдвиг измеряется на живых тиках и применяется автоматически, переход на летнее время подхватится сам. Текущее значение видно в `/status`.
- **Резерв обычных пар.** Переключатель в настройках: если живых пар в диапазоне payout меньше восьми (например, сессия PO отвалилась), в работу подмешиваются обычные валютные пары с публичным фидом, чтобы сканер не молчал. У них payout ниже целевого — такие сигналы помечаются предупреждением.

## Команды проекта

- `bun run dev` — дев-сервер (API + дашборд на одном порту).
- `bun run build` — сборка всех пакетов.
- `bun run start` / `bun run stop` — продакшен-сервер под pm2.
- `bun run lint`, `bun run typecheck` — проверки.
- `bun run db:push` — схема в базу.

Порты фиксированы в `__ports.cjs`, health-endpoint — `/api/health`. Файлы с префиксом `__` управляются шаблоном, их не трогаем.
